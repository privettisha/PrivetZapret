# PrivetZapret

Настольное приложение для Windows 10/11 и Arch Linux. Оно запускает локальные движки zapret и TG WS Proxy для выбранных сервисов. Версия 0.7.6 открывает графическое окно вместо страницы в браузере.

## Установка

**Windows:** скачайте `PrivetZapret-Windows-x64.exe`, запустите, подтвердите UAC и нажмите «Установить и включить».

**Arch Linux:** установите `nftables`. Для рабочего стола на Wayland нужен XWayland; графический запрос прав выполняет polkit. Если графического агента polkit нет, запустите файл из терминала через `sudo`.

```bash
sudo pacman -S nftables xorg-xwayland polkit
chmod +x PrivetZapret-Arch-x64
./PrivetZapret-Arch-x64
```

Служба запускается только из открытого приложения. «Выключить» останавливает её и дочерние процессы; закрытие окна делает то же самое. Если окно принудительно завершено, служба остановится после истечения короткого сигнала присутствия. Автозапуск после перезагрузки выключен. В верхнем блоке видно число обнаруженных процессов движка. «Удалить» останавливает службу, восстанавливает DNS и удаляет установленные файлы. Если обнаружена старая установленная служба, окно показывает её версию и кнопку «Установить новую версию и включить». На Arch Linux при включении активный внешний `zapret.service` останавливается, чтобы два движка не мешали друг другу. Если PrivetZapret не запустится, внешний zapret включается обратно; при обычном выключении PrivetZapret он сам не включается.

## YouTube и Telegram

Для YouTube есть профили «Стандарт», «Разделение», «Альтернативный» и «Без QUIC». На Arch Linux «Стандарт» использует встроенный `nfqws` из [zapret v72.13](https://github.com/bol-van/zapret) и параметры работающей на этой машине конфигурации: `hostfakesplit`, `--ip-id=zero`, TCP timestamp, четыре повтора и fake QUIC с шестью повторами. При обновлении с прежней версии приложение выбирает «Стандарт» и «Сбалансированный» для точного воспроизведения этих параметров. Другие профили Arch и версия Windows используют zapret2 с отдельным TCP-правилом для `googlevideo.com`, основанным на [стратегиях Flowseal](https://github.com/Flowseal/zapret-discord-youtube). В разделе «Проверка» есть отдельный запрос к примеру регионального видеосервера, потому что главная страница и `redirector.googlevideo.com` могут отвечать, когда само видео недоступно. Успешный ответ образца не подтверждает воспроизведение конкретного видео в сети пользователя.

Если TCP к видеосерверу не подключается даже при выключенном PrivetZapret, смена DPI-профиля не сможет восстановить этот маршрут. На Arch Linux можно установить [Cloudflare WARP](https://developers.cloudflare.com/warp-client/get-started/linux/) и нажать «Открыть YouTube через WARP». Приложение проверяет доступность примерного видеосервера через локальный SOCKS5-прокси WARP и открывает отдельный профиль Brave, Chrome, Chromium или Edge. PAC-настройка направляет через WARP страницу, API и видеосерверы YouTube, остальные сайты идут напрямую. Это важно: при прямой загрузке страницы YouTube может выдать адрес видеосервера, недоступного через WARP. Кнопка «Отключить видеомаршрут WARP», остановка службы и закрытие окна отключают WARP, если его подключил PrivetZapret, и возвращают прежний режим клиента. У отдельного браузерного профиля свои закладки и входы в аккаунты. На Windows этот запасной маршрут пока не реализован.

Telegram Desktop необходимо подключить к встроенному локальному MTProto прокси кнопкой «Подключить в Telegram». Он слушает только `127.0.0.1`. Режим «Медиа» направляет DC4 напрямую и использует резервный маршрут для остальных случаев. Если медиа не загружаются, можно применить «Прямой» (DC2 и DC4) либо «Только резерв». После смены маршрута переподключите Telegram. Диагностика показывает число недавних ошибок резервного маршрута, но не читает сообщения и не показывает секрет прокси. Маршруты не гарантируют работу медиа во всех сетях и дата-центрах Telegram.

## Свой DNS

В разделе DNS можно ввести полный адрес DoH, например `https://dns.example/dns-query`, либо DoT, например `tls://dns.example`. Перед включением приложение проверяет защищённый сервер. Для поиска его адреса используются прежние DNS-серверы подключения. При временном сбое защищённого сервера запросы идут к прежним DNS без шифрования.

На Windows приложение сохраняет DNS основного сетевого адаптера и ставит `127.0.0.1` (и `::1`, если IPv6 активен). На Arch Linux сохраняется исходный `/etc/resolv.conf`, включая символьную ссылку, и временно ставится локальный DNS на `127.0.0.1`. Остановка и удаление восстанавливают прежние настройки. Если другое приложение изменило `/etc/resolv.conf` во время работы, PrivetZapret не перезаписывает его при восстановлении и сохраняет резервную копию в `/opt/privetzapret/dns-state.json`. Локальный порт 53 должен быть свободен. Браузеры и VPN с собственным DNS могут обходить системную настройку.

## Сборка

Go 1.26+, C компилятор и графические библиотеки Fyne. Linux: `gcc`, OpenGL и заголовки X11. Windows: MinGW-w64. Команда `go test ./...` запускает тесты конфигурации, маршрутов и DNS. GitHub Actions сначала собирает два вспомогательных бинарника TG WS Proxy, затем встраивает их в приложение и собирает оба настольных файла. Локальная сборка из чистого исходника без этих вспомогательных файлов не сможет установить Telegram-маршрут.

В комплекте [zapret v72.13](https://github.com/bol-van/zapret) (Linux `nfqws` SHA-256 `f34615964d7321650197cd69d3f7cbfdaabe8118b5a0d57c6e41dccdff658999`), [zapret2 1.0.7](https://github.com/bol-van/zapret2) и [TG WS Proxy 1.12.0](https://github.com/Flowseal/tg-ws-proxy/tree/v1.12.0). Их лицензии находятся в `payload/common/`. Исходник TG WS Proxy закреплён на ревизии `3fc8b9ee984fc36f52d59b2323735dc8d681864d`; вспомогательный бинарник собирается из неё в CI. Графическое окно использует [Fyne](https://fyne.io/).
